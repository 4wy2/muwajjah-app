# مُوجّه — مشروع React مستقل

منصة عربية RTL للبحث عن الجامعات السعودية، مقارنة الخيارات، حساب الموزونة، بوابة الطالب وإدارة المحتوى. مشروع جديد مبني باستخدام React وTypeScript وVite؛ أُنشئ مستقلاً عن المستودعات السابقة. المستودع الجديد: [4wy2/muwajjah-platform](https://github.com/4wy2/muwajjah-platform).

## التشغيل

يتطلب Node.js 22 وnpm.

```sh
npm ci
npm run dev
```

افتح العنوان الذي يطبعه Vite. يوجد Hot Reloading أثناء التطوير.

```sh
npm test
npm run build
npm run preview
```

البناء النهائي في `dist/`. تتضمن حزمة التسليم نسخة مبنية منه للنشر اليدوي.

## إعداد Supabase

الإعداد الافتراضي في `src/lib/config.ts` هو عنوان Supabase ومفتاح **anon العام** الموجودان في المشروع المرفق. لتخصيصهما انسخ `.env.example` إلى `.env.local` وضع:

```dotenv
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-public-anon-or-publishable-key
```

كل متغير يبدأ بـ `VITE_` يصل إلى المتصفح؛ لا تضع فيه مفتاح `service_role`. تعتمد جميع القراءات والتعديلات على جلسة Supabase وسياسات RLS الموجودة. إخفاء زر أو حراسة مسار في React ليس بديلًا عن RLS.

قاعدة الدليل موجودة مسبقًا. ملفات `database/original/` مرجع مطابق للملفات المرفقة؛ **لا تشغّلها جماعيًا فوق قاعدة الإنتاج**.

لتفعيل المفضلة وسجل الموزونة، راجع وشغّل `database/001_student_features.sql` مرة واحدة في SQL Editor بمشروع Supabase المقصود. يضيف جدولين وسياسات وصول الطالب لسجلاته فقط، ومشغّلًا يعيد حساب النتيجة من أوزان المسار في الخادم. لا يغيّر سياسات جداول الدليل أو صلاحيات الإدارة الحالية. هذا الملف لم يُطبّق على قاعدة الإنتاج خلال إعداد هذه النسخة.

## ما يتضمنه المشروع

| المجال         | الوظائف                                                                                  |
| -------------- | ---------------------------------------------------------------------------------------- |
| دليل الجامعات  | بحث مؤجّل حسب الاسم/المدينة، تصفية المنطقة والنوع، بطاقات وشعارات، صفحات تفاصيل          |
| تفاصيل الجامعة | أقسام مرنة، تخصصات مجمعة بالكليات، مسارات، حاسبة وفق الأوزان المنشورة، نسب سابقة محمية   |
| المقارنة       | حتى ثلاث جامعات منشورة، مع احترام إعداد إتاحة الميزة                                     |
| حساب الطالب    | بريد وكلمة مرور، Google OAuth، استعادة كلمة المرور، الملف الشخصي                         |
| بوابة الطالب   | المفضلة، آخر 50 عملية موزونة مع استعادة أحدث الدرجات، حالة بلس وانتهاؤها                 |
| إدارة المحتوى  | جامعات وتخصصات ومسارات وأقسام ونسب، إنشاء وتعديل، نشر جماعي، سلة واستعادة                |
| الاستيراد      | معاينة JSON وCSV، فروق لكل حقل، كشف التكرار، تحقق من الجامعات المسندة، نتائج جزئية واضحة |
| الإدارة        | صلاحيات المساهمين وإسناد الجامعات، إعداد الميزات وبلس، التحليلات وتصدير JSON             |
| التجربة        | RTL، واجهة متجاوبة، وضع فاتح/داكن/النظام، تنقل باللوحة، حالات تحميل وخطأ وفراغ           |

الحذف في الإدارة نقل إلى سلة قابل للاستعادة، عبر الدالة الموجودة `guide_change_record_state`. الاستيراد يحفظ المحتوى الجديد مسودة ولا يقبل حقول الصلاحيات أو النشر من الملف. عمليات الاستيراد الكبيرة متتابعة وليست معاملة واحدة؛ تظهر السجلات التي نجحت والتي تعذرت.

## البنية

- `src/api/`: الاستعلامات والتعديلات وRPC؛ React Query للتخزين المؤقت وإعادة الجلب.
- `src/auth/`: الجلسات وحراسة المستخدم وعضوية الإدارة؛ تنظيف الذاكرة المؤقتة عند تبديل الحساب.
- `src/components/`: العرض المشترك والنوافذ والتنبيهات وحدود الأخطاء.
- `src/pages/`: الصفحات العامة وبوابة الطالب؛ تحميل كسول للصفحات.
- `src/admin/`: وحدات مستقلة للمحتوى، الاستيراد، الفريق، الميزات والتحليلات.
- `src/lib/`: أنواع البيانات، الحساب والتحقق، وتفضيلات العرض والمقارنة في Zustand.
- `database/`: الإضافة المطلوبة للطالب ومراجع المخطط الأصلي.
- `tests/`: حساب الموزونة والاستيراد، واختبارات سياسات وصول حقيقية في PostgreSQL محلي عبر PGlite.

يفصل المشروع منطق البيانات عن العرض. تُحمّل الاستعلامات الكبيرة على صفحات لمنع اقتطاع بيانات Supabase الصامت، وتُقسّم إجراءات الإدارة إلى دفعات تناسب حدود الدوال الحالية.

## تطوير الإدارة

الإدارة لها مدخل مستقل `/admin/login` وتصميم منفصل عن صفحات الزوار، داخل المشروع نفسه. شغّل `npm run dev:admin` أثناء تطويرها. [دليل تطوير الإدارة](docs/ADMIN_DEVELOPMENT.md) يشرح إضافة الأقسام والصلاحيات وحقول المحتوى.

## النشر والتحقق

راجع [دليل النشر](docs/DEPLOYMENT.md) لإعداد Netlify وOAuth، و[نتائج التحقق](docs/VALIDATION.md) لمعرفة ما جرى اختباره وما يتطلب حسابًا فعليًا. إعداد Netlify وملف CI جاهزان، ولم يُستخدم أو يُعدّل أي مستودع GitHub قائم.
