# تطوير لوحة إدارة مُوجّه

الإدارة مساحة مستقلة في الواجهة والمسارات عند `/admin`، ضمن تطبيق React واحد ومستودع واحد. تستخدم Supabase Auth نفسه الذي تستخدمه بوابة الطالب. استقلال صفحة الدخول لا ينشئ نظام حسابات آخر، ولا تمنح صفحة الدخول أي صلاحية بذاتها.

## الدخول والصلاحيات

| المستخدم             | المدخل                            | شرط الوصول                                  |
| -------------------- | --------------------------------- | ------------------------------------------- |
| الطالب               | `/auth/login`                     | جلسة Supabase صالحة                         |
| المالك أو المساهم    | `/admin/login`                    | جلسة صالحة وعضوية مفعّلة في `guide_admins`  |
| استعادة حساب الإدارة | `/admin/forgot` ثم `/admin/reset` | رابط الاستعادة المرسل بواسطة Supabase       |
| عودة Google للإدارة  | `/admin/callback`                 | إعداد مزود Google وروابط السماح في Supabase |

زائر قسم إدارة داخلي يُحوّل إلى تسجيل دخول الإدارة مع حفظ وجهته. حساب الطالب المسجّل لا يحصل على وصول للإدارة، وتظهر له رسالة واضحة مع إمكانية تسجيل الخروج وتبديل الحساب. الصفحات الحساسة للفريق وبلس والتحليلات متاحة للمالك فقط؛ الاستيراد يتطلب صلاحية تعديل. المساهم يرى الجامعات المسندة إليه.

إعداد أول مالك يتم بواسطة مالك قاعدة البيانات عبر آلية المشروع الحالية؛ لا يوجد زر يجعل المستخدم نفسه مالكًا. إضافة المساهمين بعد ذلك من `/admin/team`. إنشاء حساب طالب أو تعديل بياناته الشخصية لا يمنح دور إدارة.

فحص الأدوار في React لتجربة الاستخدام فقط. يجب أن تظل عمليات القراءة والكتابة وRPC محكومة بـRLS الموجودة. لا تستخدم مفتاح `service_role` في الواجهة، ولا تنقل الصلاحيات إلى localStorage أو بيانات المستخدم القابلة للتعديل.

## أين تعدّل؟

| المهمة                                         | الملف                          |
| ---------------------------------------------- | ------------------------------ |
| مدخل الإدارة ومسارات الدخول والحراسة           | `src/admin/AdminApp.tsx`       |
| قائمة الإدارة وتخطيط مساحة العمل               | `src/admin/AdminLayout.tsx`    |
| إضافة قسم وتعريف عنوانه وأيقونته وصلاحية عرضه  | `src/admin/modules.tsx`        |
| مظهر الإدارة فقط                               | `src/admin/admin.css`          |
| قواعد عرض أقسام الإدارة                        | `src/admin/access.ts`          |
| حقول الجامعات/التخصصات/المسارات/الأقسام والنسب | `src/admin/specs.ts`           |
| نموذج CRUD المشترك                             | `src/admin/ContentManager.tsx` |
| عمليات البيانات وحفظها                         | `src/api/admin.ts`             |
| عمليات الدخول واستعادة كلمة المرور             | `src/api/auth.ts`              |
| نموذج المصادقة المشترك بنصوص مستقلة لكل بوابة  | `src/pages/Auth.tsx`           |

## التطوير المحلي

```sh
npm ci
npm run dev:admin
```

يفتح Vite صفحة دخول الإدارة مباشرة، والتغييرات تظهر مع Hot Reloading. استخدم حساب فريق موجودًا في بيئة تطوير مناسبة للتحقق من الصفحات المحمية. لا تغيّر RLS أو تضف تجاوزًا للحراسة لأجل معاينة الواجهة.

## إضافة قسم إدارة جديد

1. أنشئ مكون الصفحة داخل `src/admin/`، واجعل استعلاماته في `src/api/`.
2. أضف استيرادًا كسولًا إلى `modules.tsx`، مثل:

```tsx
const Reports = lazy(() => import("./Reports"));
```

3. أضف تعريفًا واحدًا إلى `adminModules`:

```tsx
{ path: "reports", label: "التقارير", icon: ChartNoAxesCombined,
  access: "owner", element: <Reports /> }
```

تظهر القائمة ويُنشأ المسار `/admin/reports` من التعريف نفسه. أنواع الإتاحة هي `member` أو `editor` أو `owner`. لا تحتاج لتعديل موجه الصفحات العام في `src/main.tsx`. كل قسم يُحمّل عند فتحه، وله حالة تحميل وحد خطأ داخل مساحة المحتوى، فتظل قائمة الإدارة متاحة إذا فشل قسم.

إذا احتاجت الميزة جدولًا أو RPC جديدًا، أضف migration مستقلًا وسياسات RLS المناسبة وراجعه قبل تطبيقه. إعداد إتاحة القسم في السجل لا ينشئ صلاحية قاعدة بيانات.

## تعديل حقل أو ميزة قائمة

حقول CRUD موصوفة في `specs.ts`؛ تعديلها ينعكس على النموذج والتحقق ومعاينة الاستيراد. لا تضف عمودًا جديدًا للواجهة قبل وجوده في قاعدة البيانات. ميزات بلس وإتاحة المقارنة والنسب تدار من `/admin/access` وتُقرأ من دوال المشروع القائمة.

قبل رفع التغيير شغّل `npm test` و`npm run build`. يكرر GitHub Actions هذين الفحصين. عند ربط Netlify بالمستودع، يؤدي الدفع إلى فرع الإنتاج إلى إعادة البناء والنشر.

## حالة التحقق

تم فحص فصل واجهات الدخول وتحويل الزائر بين المسارات، وحالات استعادة كلمة المرور، وقواعد عودة تسجيل الدخول والأدوار. لا توجد اختبارات دخول أو تعديلات محتوى بحساب إدارة فعلي حتى الآن. يلزم التحقق بحساب مالك ومساهم بعد ضبط روابط Supabase ونشر الموقع.
