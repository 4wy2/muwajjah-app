# نشر مشروع مُوجّه الجديد

## Netlify

أُعد `netlify.toml` بالقيم التالية:

| الإعداد           | القيمة          |
| ----------------- | --------------- |
| Build command     | `npm run build` |
| Publish directory | `dist`          |
| Node              | `22`            |

قاعدة SPA تعيد المسارات غير المطابقة إلى `index.html`، حتى يعمل فتح `/student/dashboard` أو تحديث صفحة الجامعة مباشرة. توجد نسخة منها في `public/_redirects` للنشر اليدوي.

يمكن نشر محتويات `dist/` في **مشروع Netlify جديد** من واجهة النشر اليدوي. للنشر التلقائي، اربط المستودع الجديد `4wy2/muwajjah-app` بمشروع Netlify جديد. ملفات المصدر موجودة في جذر المستودع. ملف `.github/workflows/ci.yml` يشغّل الاختبارات والبناء عند الدفع أو طلب الدمج في هذا المستودع.

إذا خصصت اتصال Supabase، أضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` في إعدادات البناء ثم أعد البناء. لا يتغير اتصال حزمة مبنية سابقًا بمجرد تغيير متغيرات البيئة.

## تسجيل الدخول وGoogle OAuth

بعد الحصول على عنوان النشر النهائي، حدّث **Authentication → URL Configuration** في Supabase:

1. ضع أصل الموقع النهائي في Site URL.
2. أضف عنوان الموقع مع `/auth/callback` و`/auth/reset` و`/admin/callback` و`/admin/reset` إلى Redirect URLs.
3. أضف عنوان التطوير المحلي بالمسارات الأربعة نفسها عند الحاجة للتطوير.
4. فعّل Email وتأكيد البريد حسب إعدادات المشروع.
5. فعّل Google provider في Supabase، وضع معرّف العميل وسره هناك فقط. أضف Callback URL الذي يعرضه Supabase إلى إعدادات عميل Google.
6. فعّل ظهور Google في لوحة مُوجّه `/admin/access`. إعداد ظهور الزر وحده لا يهيئ مزود Google.

يستخدم التطبيق PKCE؛ يجب فتح رسالة تأكيد البريد أو الاستعادة في المتصفح نفسه الذي بدأ الطلب حتى تتوفر قيمة التحقق المحفوظة فيه.

## قاعدة البيانات

شغّل الإضافة `database/001_student_features.sql` في قاعدة الدليل الصحيحة بعد مراجعتها. التطبيق لا ينفذ تغييرات مخطط تلقائيًا ولا يستخدم مفتاحًا إداريًا. قبل الإضافة ستظهر رسالة تعذر تحميل/حفظ المفضلة وسجل الموزونة، بينما يبقى الدليل العام متاحًا.

حالة ميزات المقارنة والنسب السابقة مأخوذة من `guide_feature_state`. لا تتجاوز الواجهة إعدادات hidden/locked. يتطلب حساب الموزونة وجود مسار منشور بأوزان صحيحة مجموعها 100؛ المسارات ذات مجموع صفر لا تحسب موزونة.

## اختبار حسابات حقيقية بعد التهيئة

- طالب: إنشاء حساب وتأكيده، دخول وخروج، استعادة كلمة المرور وGoogle.
- طالب: حفظ جامعة وتخصص كمفضلة، إعادة تحميل الصفحة، حفظ موزونة واستعادة درجاتها.
- طالب آخر: لا يستطيع قراءة مفضلة أو درجات الطالب الأول.
- بلس: ظهور النسب عند الصلاحية وحجبها عند الانتهاء أو الإلغاء.
- مساهم: عرض وتعديل الجامعات المسندة فقط، مع رفض الطلبات خارج الصلاحية في الخادم.
- مالك: CRUD وسلة واستعادة ونشر جماعي، واستيراد ملف صغير بعد مراجعة الفروق.
- فتح مسار داخلي مباشرة على عنوان Netlify النهائي.

المصادر الرسمية: [Vite على Netlify](https://docs.netlify.com/build/frameworks/framework-setup-guides/vite/)، [روابط إعادة التوجيه في Supabase](https://supabase.com/docs/guides/auth/redirect-urls).
